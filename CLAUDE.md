# CLAUDE.md – Rezepte-App

Diese Datei gibt Claude Code den Kontext für dieses Repository. Sprache im Gespräch und in der App-Oberfläche: **Deutsch (Österreich)**. Code, Bezeichner, Commits und Kommentare: **Englisch**.

## Projekt in einem Satz

Flutter-App (zuerst Android, später iOS) für einen Haushalt mit mehreren Personen: Rezepte verwalten, per Foto oder Link importieren, gemeinsame Einkaufsliste und Vorrat. Beim Kochen wird der Vorrat abgezogen, und die App zeigt, was man mit dem Vorrat kochen kann. Offline-first, Sync über Firebase, Verteilung über Google Play (Testgruppe).

## Datenmodell (Firestore)

Alle Haushaltsdaten liegen unter `households/{householdId}`. Außerhalb gibt es nur `users` und `invites`.

```
users/{uid}
  displayName, householdIds: [string], createdAt

invites/{code}         # 6 chars, no 0/O/1/I/L; get only, never list
  householdId

households/{hid}
  name, memberIds: [uid], inviteCode, createdAt
  joinCode?            # set by a joiner; rules check joinCode == inviteCode

households/{hid}/ingredients/{ingredientId}
  name                 # "Mehl glatt"
  synonyms: [string]   # ["Weizenmehl", "Mehl"]
  aisle                # produce|bread|dairy|meat|baking|dry|spices|frozen|drinks|other
  baseUnit             # g|ml|pcs
  conversions: {unit: factorToBase}   # {"EL": 10, "Packung": 1000}
  alwaysAvailable: bool               # Salz, Pfeffer, Wasser, Öl

households/{hid}/recipes/{recipeId}
  title, category      # cooking|cake|cookies|<custom>
  tags: [string], servings: int, prepMinutes, cookMinutes
  photoPaths: [string] # Cloud Storage paths
  rating: 0-5, notes
  source: {type: manual|ocr|url, url?}
  ingredients: [{ingredientId?, amount?, unit?, note?, name?, rawText}]
  ingredientIds: [string]     # denormalized for queries
  steps: [{text, timerSeconds?}]
  createdBy, createdAt, updatedAt

households/{hid}/pantry/{ingredientId}       # doc id = ingredient id
  amount               # always in baseUnit
  location             # fridge|pantry|freezer
  minAmount?, expiresOn?, updatedAt

households/{hid}/shopping/{itemId}
  ingredientId?, text, amount?, unit?, aisle
  checked: bool, fromRecipeId?, addedBy, createdAt

households/{hid}/mealplan/{yyyy-MM-dd}
  recipeIds: [string]

households/{hid}/cookLog/{logId}
  recipeId, servings, cookedAt
  deductions: [{ingredientId, amountBase}]
  undone: bool
```

## Fachliche Regeln

- **Einheiten:** Jede Zutat hat eine Basiseinheit (g, ml, pcs). Allgemeine Umrechnungen sind fix in `core/units` (kg→g, l→ml, EL = 15 ml, TL = 5 ml, Prise, Msp.). Zutatenbezogene Umrechnungen kommen aus `ingredient.conversions`. Fehlt eine Umrechnung, fragt die UI einmal nach und speichert sie an der Zutat. Nie stillschweigend raten.
- **Zuordnung von Zutatnamen** (`core/matching`): 1. exakter Name, 2. Synonym, 3. normalisiert (Kleinschreibung, Umlaute, Plural, Zusätze wie „weich“, „gehackt“ entfernt), 4. ähnlichster Vorschlag (markiert als unsicher), 5. neue Zutat. `rawText` bleibt immer erhalten.
- **Vorrat ändern** nur mit `FieldValue.increment`, nie Menge lesen und überschreiben. So bleiben gleichzeitige Offline-Änderungen mehrerer Handys korrekt.
- **„Gekocht“:** Dialog zeigt alle geplanten Abzüge (skaliert auf gewählte Portionen), jede Menge editierbar. Nach Bestätigen: Batch mit Increments + `cookLog`-Eintrag. „Rückgängig“ bucht die Deductions aus dem Log zurück. Vorrat darf nicht unter 0 fallen (auf 0 kappen, Hinweis zeigen).
- **„Was kann ich kochen?“** wird lokal berechnet: pro Rezept Anteil der Zutaten, die der Vorrat abdeckt (alwaysAvailable zählt als vorhanden), plus Liste der fehlenden. Sortierung: abgedeckt absteigend, dann fehlende Anzahl.
- **Fehlendes einkaufen:** fehlende Differenz je Zutat auf die Einkaufsliste; existiert die Zutat schon unabgehakt, Menge addieren statt doppelt anlegen.
- **Mindestbestand:** fällt `amount` unter `minAmount`, Eintrag auf die Einkaufsliste (einmalig, kein Duplikat).
- **Suche** läuft lokal über die gecachten Rezepte (Firestore hat keine Volltextsuche). Haushalte sind klein, das reicht.
- **Zutaten zusammenführen:** Doppelte (z. B. „Sahne“ und „Schlagobers“) erkennt `IngredientMatcher.findDuplicates`; die Zutaten-Verwaltung zeigt sie an. Beim Zusammenführen werden Name und Synonyme der aufgelösten Zutat Synonyme der behaltenen; Rezepte, Vorrat (nur bei gleicher Basiseinheit) und Einkaufsliste werden umgehängt.
- **Neue Zutat beim Speichern:** Zeilen ohne Treffer legen eine Zutat an (Basiseinheit aus der Einheit geraten, Abteilung `other`). Unsichere Treffer werden im Rezept-Editor markiert und können per Tippen geändert werden.
- **Österreichische Begriffe** sind gleichwertig: Topfen/Quark, Schlagobers/Sahne, Paradeiser/Tomaten, Erdäpfel/Kartoffeln, Karfiol/Blumenkohl, Marillen/Aprikosen, Faschiertes/Hackfleisch, Mehl glatt/griffig.

## Offline & Sync

- Firestore-Offline-Persistenz ist an. Jede Schreiboperation muss offline funktionieren und darf nicht auf ein Server-Ergebnis warten (kein `await` auf Writes, das die UI blockiert).
- Online-pflichtig sind nur: KI-Erkennung, Link-Import, Barcode-Produktsuche, Foto-Upload. Ohne Netz: Auftrag in eine lokale Warteschlange, beim nächsten Online-Sein verarbeiten, Status in der UI zeigen.
- Fotos vor dem Upload auf max. 1600 px Kante und JPEG ~80 % verkleinern.

## Sicherheit

- Firestore- und Storage-Regeln in `firestore.rules` / `storage.rules` im Repo pflegen. Lesen/Schreiben unter `households/{hid}` nur, wenn `request.auth.uid in memberIds`. Unterpfade mit `match /{collection}/{document=**}` matchen (ein nacktes `{document=**}` matcht in v2 auch das Haushalt-Dokument selbst). Jede Regeländerung braucht einen Test in `test_rules/`.
- Regeln sind (noch) nicht automatisch deployed: in der Firebase-Konsole einfügen oder `firebase deploy --only firestore:rules`.
- App Check für Firebase AI Logic aktivieren.
- Keine Secrets committen (Keystore, Service-Account-JSON). `firebase_options.dart` und `google-services.json` dürfen ins Repo, der Schutz läuft über Regeln und App Check.
- KI-Modellname nicht hart codieren: Remote-Config-Schlüssel `ai_model`.

## KI-Import

- Prompt verlangt strukturiertes JSON nach festem Schema: `{title, servings, prepMinutes?, cookMinutes?, ingredients: [{amount?, unit?, name, note?}], steps: [string]}`. Antwort mit dem Schema validieren; bei Fehler einmal neu fragen, sonst Rohtext im Prüf-Bildschirm zeigen.
- Jeder Import endet im **Prüf-Bildschirm**. Nichts wird ungeprüft gespeichert.
- Link-Import: zuerst JSON-LD `schema.org/Recipe` aus dem HTML lesen, nur wenn das fehlt, Seitentext an die KI.

## UI

- Bottom-Navigation: **Rezepte · Wochenplan · Einkauf · Vorrat**. Einstellungen über Profilbild oben rechts.
- Kategorien (Kochen, Kuchen, Kekse, eigene) sind Filter-Chips im Rezepte-Reiter, keine eigenen Reiter.
- Alle Texte über `flutter_localizations` / ARB-Dateien (`lib/l10n/app_de.arb`), keine hart codierten Strings in Widgets.
- Material 3, Hell- und Dunkelmodus, große Touch-Ziele (Kochen mit nassen Händen). Theme in `lib/app/theme.dart`, Routen in `lib/app/routes.dart` / `router.dart` (StatefulShellRoute, Einstellungen als Vollbild-Route über der Shell).

## CI (GitHub Actions)

- Firebase-Konfiguration: `android/app/google-services.json` (darf ins Repo). Die Gradle-Plugins google-services und Crashlytics werden nur angewendet, wenn die Datei existiert; ohne sie startet die App mit einem Hinweis-Bildschirm. Login mit Google läuft über `FirebaseAuth.signInWithProvider` (braucht SHA-1 des Upload-Keys in Firebase; die CI schreibt die Fingerabdrücke in die Job-Zusammenfassung).
- `.github/workflows/ci.yml`: Job `rules` testet die Firestore-Regeln im Emulator. Job `build`: bei jedem Push/PR (und manuell) `flutter analyze`, `flutter test`, dann Release-APK und App-Bundle (AAB) bauen, beide als Artefakt. Sind die Keystore-Secrets gesetzt, wird mit dem Upload-Key signiert, sonst mit dem Debug-Key (APK installierbar, AAB nicht für Play geeignet).
- Signatur: `android/app/build.gradle.kts` liest `android/key.properties` (gitignored, in CI aus Secrets erzeugt).
- `.github/workflows/release.yml`: bei Tag `v*` signiertes App-Bundle bauen und in den Play-Track `internal` hochladen.
- Secrets: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `PLAY_SERVICE_ACCOUNT_JSON`.
- `versionCode` aus der GitHub-Run-Nummer ableiten.
